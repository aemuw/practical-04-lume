# Практична робота №5 — Адаптивний вебінтерфейс LUME

Продовження [ПР №4](https://github.com/aemuw/practical-04-lume): збережено всі чотири HTML-сторінки, зображення, семантику та DOM-порядок. Перероблено спільний `styles/main.css`. Для роботи сайту не потрібні JavaScript, пакети чи збірка.

## Mobile-first та fluid container

Базові правила розраховані на вузький екран: header, пошук і hero вертикальні; поля займають доступну ширину; текст кнопок переноситься. `min-width` media queries розширюють композицію.

```css
.container {
    inline-size: min(100% - 2rem, 80rem);
    margin-inline: auto;
}
```

За базового шрифту 16px на 320px доступні 288px основного вмісту. На desktop боковий простір збільшено до 2rem із кожного боку, максимум вмісту — 80rem. `box-sizing: border-box` застосовано глобально. Висота текстових блоків не фіксується; типографіка й відступи використовують `clamp()`.

## Content-driven breakpoints

| Умова | Зміна та причина |
|---|---|
| До 44rem | Вертикальний header, пошук і hero: достатньо місця для тексту та controls |
| `min-width: 44rem` (704px за базових 16px) | Hero у дві колонки; пошук у рядок; header допускає wrap. Для кожної hero-колонки залишається близько 20rem, меню ще займає окремий рядок |
| `min-width: 72rem` (1152px) | Бренд, повне меню й облікові посилання вже поміщаються в один рядок; збільшуються відступи |

Breakpoints визначені місткістю вмісту, а не моделями пристроїв. Додатково перевірено ширини 703/704 і 1151/1152px. Кількість колонок каталогу змінюється незалежно від цих media queries.

## Flexbox і Grid

**Flexbox:** `.site-nav ul`, `.account-nav` — одновимірні групи посилань; `.form-actions` — кнопки з `flex: 1 1 12rem`; `.search-form` — пошук; `.product-card` — вертикальний вміст із посиланням унизу. Групи навігації, пошуку й дій мають `flex-wrap` і `gap`.

**Grid:** `.hero` — головна композиція; `.collection-list` — основна повторювана сітка:

```css
.collection-list {
    display: grid;
    grid-template-columns: repeat(auto-fit, minmax(min(100%, 17rem), 1fr));
    gap: 1.25rem;
}
```

`auto-fit` додає стільки колонок, скільки поміщається. `17rem` — бажаний мінімум картки; `min(100%, 17rem)` дозволяє звузити її на телефоні; `1fr` розподіляє вільне місце. На 320px каталог має одну колонку, на 768px — дві, на 1280px — чотири. Для grid items задано `min-inline-size: 0`.

## Три знайдені проблеми та виправлення

Початкові вимірювання — `evidence/before.json`, підсумкові — `evidence/responsive-audit.json`.

| Проблема | Причина | Виправлення |
|---|---|---|
| На 320px основному вмісту залишалося 256px | Старий контейнер мав по 2rem padding | Fluid container із відступами по 1rem дає 288px; зменшено padding форм |
| Нерозривний URL розширював сторінку | Переносилися заголовки, але не довільні абзаци | `overflow-wrap: anywhere` на body; `min-inline-size: 0`; гнучкі кнопки |
| На 768px hero залишався вертикальним | Два flex-елементи з basis по 25rem не поміщалися | Grid із двома `minmax(0, 1fr)` колонками від 44rem |

`overflow-x: hidden` для маскування помилок не застосовано. Довгі назви не обрізаються фіксованою висотою. Зображення мають HTML width/height, `max-inline-size: 100%`, `block-size: auto`. Окремих ресурсів зображень інших розмірів немає, тому штучний `srcset` не додано.

## Доступність і форми

- HTML і DOM-порядок збережені; `order`, `row-reverse`, перестановка елементів через Grid не застосовуються.
- Збережено `label`, `fieldset/legend`, `autocomplete`, нативну HTML-валідацію.
- `:focus-visible` має рамку 3px; skip-link відкривається через Tab і переводить фокус у main.
- Основні кнопки та навігаційні посилання мають мінімальну висоту 2.75rem; текст кнопок переноситься.
- `prefers-reduced-motion: reduce` вимикає наявні transitions і задає звичайне прокручування.

Пошук використовує GET: запит видно в URL, але каталог не фільтрується. Форми використовують POST на умовні `api/login`, `api/register`, `api/products`. Backend відсутній: після коректного надсилання статичний сайт не створює обліковий запис і не зберігає товар. Перевірка збігу паролів також не реалізована. Це збережені межі навчального проєкту.

## Тестування

Автоматичний аудит підготовленої версії у Chromium-based Microsoft Edge: **87 перевірок, 0 помилок**. Версія браузера й результати — у JSON. Це не твердження про самостійні дії студента.

| Перевірка | Результат |
|---|---|
| Усі 4 сторінки: 320, 360, 390, 430, 768, 900, 1280, 1440px | Немає горизонтального overflow, controls і зображення в межах viewport |
| Додатково 640, 703, 704, 1151, 1152px | Перевірено проміжні значення й межі переходів |
| Довгі нерозривні заголовки/URL на 320px | Текст переноситься |
| Порожній каталог і 24 картки на 320px | Переповнення відсутнє |
| Tab → skip-link → Enter → main → Tab | Skip-link працює, наступний елемент має видимий focus |
| Порожні форми | Валідація блокує надсилання; повідомлення не розширюють сторінку |
| Емуляція reduced motion | Наявні transitions вимкнено |
| CSS `zoom: 2` на 1280px | Тест навантаження компонування пройдено |
| Справжній browser zoom 200% | **Потребує ручної перевірки**; CSS zoom не підміняє цей пункт |

12 скриншотів усіх сторінок на 360/768/1280px — у `evidence/`. Перед здачею виконайте справжній zoom 200%, повний маршрут клавіатурою та внесіть свої результати до README і звіту.

### Повторний аудит (не потрібний для запуску сайту)

Потрібні Node.js, Playwright і Chromium. Із кореня проєкту:

```powershell
npm install --no-save --package-lock=false playwright
npx playwright install chromium
node tools/responsive-audit.cjs
```

Скрипт сам запускає й закриває тимчасовий локальний HTTP-сервер. Змінна `BROWSER_PATH` може вказати вже встановлений Chromium-браузер. Сайт працює без цих інструментів.
