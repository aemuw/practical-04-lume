# Практична робота №4 — CSS-оформлення LUME

LUME — навчальний магазин смарт-речей для дому. Ця версія продовжує HTML-структуру практичної №2 і форми практичної №3 та додає зовнішній CSS. Усі чотири сторінки оформлено одним файлом `styles/main.css`. JavaScript і Backend не додавалися.

За основу використано локальну підготовлену версію практичної №3 з цієї розмови. Якщо ваш GitHub-репозиторій практичної №3 має додаткові зміни, перенесіть їх у цю версію перед здачею.

## Структура та запуск

```text
practical-04-lume/
├── index.html
├── login.html
├── register.html
├── product-form.html
├── styles/main.css
├── images/
│   ├── lume-table.png
│   ├── lume-socket.png
│   ├── lume-switch.png
│   └── lume-sense.png
├── README.md
└── .gitignore
```

Відкрийте `index.html` у браузері. Складання проєкту й встановлення пакетів не потрібні. CSS підключений однаково до кожної сторінки:

```html
<link rel="stylesheet" href="styles/main.css">
```

У HTML немає inline styles або `<style>`. Файл містить послідовні розділи: tokens і базові правила, компонування, компоненти, utilities та доступні стани.

## Відповідність макету Figma

Візуальний орієнтир — експорт власного макета з практичної №1, `pr1.pdf`, desktop-сторінка LUME. Використано світлий кремовий фон, темну типографіку й кнопки, помаранчевий акцент, білі округлі картки та композицію головного блоку з текстом і товаром. Чотири зображення товарів витягнуто з наданого PDF-експорту; додаткові зображення з інтернету не завантажувалися.

Свідомі адаптації: акцент затемнено для контрасту; пошук має постійний видимий підпис і кнопку; навігацію доповнено формами; нові форми оформлено в стилі LUME, оскільки відповідних екранів входу, реєстрації та адміністрування в експорті не було. Використано Arial/Segoe UI без завантаження шрифтів. Точні параметри оригінального Figma-файлу не отримано, тому не стверджується піксельна тотожність.

## Design tokens

| Властивість | Значення | Призначення |
|---|---|---|
| --color-text | #121413 | Основний текст і темні кнопки |
| --color-muted | #616a63 | Допоміжний текст і контрастні межі controls |
| --color-background | #f6f3eb | Кремовий фон сторінки |
| --color-surface | #ffffff | Картки, форми та поля |
| --color-border | #d9d2c4 | Декоративні межі секцій і карток |
| --color-accent | #bd3500 | Акцент, hover, focus і validation |
| --space | 0.5rem | Базовий відступ, інші відступи — кратні через calc() |
| --radius | 1.5rem | Основний радіус, для менших компонентів — його частка |

Основні кольори й відступи утворюють вісім tokens. Декоративна світла межа не використовується як єдина межа текстових полів: controls мають темніший `--color-muted`.

## Box model та компоненти

`box-sizing: border-box` застосовано до всіх елементів і псевдоелементів. `body` має margin=0; повного reset нативних controls немає. `font: inherit` узгоджує поля й кнопки з текстом. `.container` задає максимальну ширину, бокові відступи та центрування.

Основні класи: `.site-header`, `.site-nav`, `.hero`, `.card`, `.product-card`, `.form-panel`, `.field-control`, `.choice-control`, `.button`, `.button--secondary`, `.site-footer`. Текстові картки не мають fixed height; довгий вміст розширює їх. `block-size: 100%` карток каталогу лише вирівнює їх у межах flex-рядка, без фіксованої висоти в пікселях. Квадратна пропорція зображення й компактні розміри checkbox допустимі й не обмежують текст.

Локальний Flexbox із wrap використано для header, hero, каталогу й дій форми. Позиціонування absolute застосовано тільки до skip-link, щоб він з’являвся при фокусі. Уся головна сторінка залишається в normal flow. Повну систему адаптивних breakpoints та Grid залишено для практичної №5; media query зараз використовується тільки для reduced motion.

## Стани

| Компонент | Реалізація |
|---|---|
| Посилання | default, visited, hover, focus-visible |
| Кнопка | hover, active, focus-visible, disabled |
| Поле | hover, focus-visible, user-invalid, disabled |
| Навігація | aria-current=page на відповідній сторінці форми |
| Валідація | Нативна HTML-перевірка, змінена межа та текст `.field-error` |
| Reduced motion | transitions вимикаються через prefers-reduced-motion: reduce |

Валідація використовує `:user-invalid`: повідомлення не показуються одразу на порожній формі. Після взаємодії або спроби надсилання з’являється текстова підказка; колір не є єдиним сигналом. У старих браузерах без цього псевдокласу залишається нативна HTML-валідація та звичайні підказки.

Disabled-правила реалізовані, але справжні поля не вимкнено без потреби. Для перевірки стану атрибут `disabled` тимчасово додано тільки в тестовому браузері. У файлах він не збережений. Змінюються лише color, background-color і border-color; transition: all не використовується.

## Два діагностовані й виправлені конфлікти CSS

Це фактичні проблеми першої перевіреної версії, а не твердження, що студент уже самостійно виконав DevTools-перевірку. Дані до й після виправлення збережено в `evidence/css-before.json` і `evidence/css-after.json`.

### 1. Checkbox успадкував ширину текстового поля

У першій версії input із класами `field-control choice-control` отримав `inline-size: 100%` із `.field-control`. Виміряна ширина checkbox становила приблизно **523,34 px** при 1440 px області перегляду; це руйнувало розташування підпису.

Виправлення: у `.choice-control` після базового правила задаються `inline-size: 1.125rem`, `block-size: 1.125rem`, `padding: 0`, `flex: 0 0 auto`. За базових 16 px це **18 px**. Специфічність двох class selectors однакова — 0-1-0; для inline-size перемагає правило, розташоване пізніше. Нативний вигляд checkbox/radio та семантика збережені.

Як перевірити в DevTools: виберіть `#product-ivory`, у Styles знайдіть inline-size обох класів; загальне 100% має бути перекреслено. У Computed перевірте inline-size=18px.

### 2. Базова кнопка перекрила secondary variant

У першій версії `.button--secondary` було записано перед `.button`. Кнопка-посилання «Скасувати» замість прозорого фону отримала **rgb(18, 20, 19)** і білий текст.

Виправлення: modifier розміщено після базового правила; для відвіданого посилання додано `.button--secondary:visited`. Фактичний фон у звичайному стані тепер **rgba(0, 0, 0, 0)**, текст — **rgb(18, 20, 19)**. Для звичайного стану селектори `.button` і `.button--secondary` мають однакову специфічність 0-1-0, тому порядок має значення. Hover/active/disabled визначено після базових variants. `!important` не застосовано.

Як перевірити в DevTools: виберіть посилання з `button button--secondary`, знайдіть background у Styles та Computed. У звичайному стані потрібне прозоре значення; наведіть курсор окремо для перевірки hover.

## Перевірки

- Microsoft Edge 155.0.4283.45: **65 перевірок форм і семантики**, **52 перевірки CSS і доступних станів** — усі успішні.
- Nu HTML Checker: **0 помилок і 0 попереджень** у кожному з чотирьох HTML-файлів.
- Text/background contrast: приблизно 16,68:1; допоміжний текст/білий фон 5,60:1; акцент/білий фон 5,72:1; білий текст темної кнопки 18,50:1.
- Перевірено фокус клавіатурою, skip-link, Enter, Space, radio arrows, назви полів, FormData, помилкові й валідні значення.
- При ширині 1440 px та 720 CSS px горизонтального переповнення немає. 720 CSS px — перевірка компонування, еквівалентна 200% при 1440 px; справжній browser zoom=200% потрібно повторити вручну за посібником.
- Довгий опис не обрізається й не спричиняє горизонтального переповнення. Скринридер і всі браузери не перевірялись; це базова перевірка, а не повний WCAG-аудит.

Деталі: [CHECKS.md](CHECKS.md). Скриншоти й первинні результати містяться в `evidence/`.

## Форми та межі проєкту

HTML-валідація, autocomplete і GET/POST з практичної №3 збережені. Пошук показує запит у URL, але не фільтрує каталог. POST-маршрути `api/login`, `api/register`, `api/products` умовні. Входу, збереження товарів, перевірки збігу паролів та прав адміністратора ще немає. На статичному хостингу після коректного надсилання можлива помилка маршруту. Для демонстрації використовуються лише вигадані дані.

Таблиця валідації й пояснення form data: [FORMS.md](FORMS.md).
