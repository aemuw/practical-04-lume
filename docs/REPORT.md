## Тема та мета

Створення адаптивного вебінтерфейсу. Адаптація сайту LUME з ПР №4 із застосуванням mobile-first, Flexbox, CSS Grid, fluid sizing і content-driven media queries.

## Зміни у підготовленій версії

1. Збережено HTML-структуру чотирьох сторінок і логічний DOM-порядок.
2. Контейнер перероблено на fluid: `inline-size: min(100% - 2rem, 80rem)`.
3. Базові стилі розраховані на вузький екран. Media queries від 44rem і 72rem розширюють композицію за наявності місця.
4. Flexbox використано в навігації, пошуку, групі кнопок форми й усередині карток.
5. Каталог використовує Grid: `repeat(auto-fit, minmax(min(100%, 17rem), 1fr))`. Hero також використовує Grid.
6. Додано перенос довгих рядків, адаптовано відступи форм і кнопки; збережено гнучкі зображення, видимий focus і reduced motion.
7. Оновлено README з поясненнями й результатами тестування.

## Проблеми та виправлення

1. На 320px старий контейнер залишав 256px для вмісту. Новий залишає 288px.
2. Нерозривні URL переповнювали сторінку. Додано `overflow-wrap: anywhere` і гнучкі обмеження ширини.
3. Hero на 768px не переходив у дві колонки через basis по 25rem. Застосовано Grid і перехід від 44rem.

## Контрольні питання

1. **Mobile-first:** базові стилі для вузького екрана, розширення через `min-width`.
2. **Breakpoints:** визначаються тим, коли вміст комфортно поміщається в ширшу композицію.
3. **Flexbox:** зручний для одного напряму — навігації, кнопок, вмісту картки.
4. **Grid:** зручний для колонок і рядків каталогу та головної композиції.
5. **auto-fit/minmax:** додають стільки колонок, скільки поміщається; задають мінімальну та гнучку максимальну ширину.
6. **order:** може роз'єднати видимий порядок і порядок читання/Tab у DOM.
7. **Overflow:** порівняти scrollWidth і clientWidth та знайти елемент, що виходить за viewport.
8. **overflow-x:hidden:** приховує наслідок, може обрізати вміст і focus, не усуває причину.
9. **Zoom 200%:** зменшує доступний простір у CSS-пікселях; компонування має перебудуватися без втрати дій. Власний результат додайте після перевірки.
10. **prefers-reduced-motion:** враховує побажання користувача; у LUME вимикає transitions і залишає звичайне прокручування.
