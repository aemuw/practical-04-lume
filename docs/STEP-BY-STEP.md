# ПР №5: від готових файлів до GitHub, покроково

## 1. Що вже підготовлено

Ця папка — клон вашого `aemuw/practical-04-lume` з історією Git та окремою гілкою `practical-05`. Сторінки та зображення взято з ПР №4; оновлено `styles/main.css`, README, додано матеріал для звіту й перевірки. Упроваджувати CSS повторно не потрібно, якщо ви відкриваєте саме цю папку.

Git зберігає версії на комп'ютері. GitHub зберігає відправлені версії в інтернеті. Commit — збереження версії в Git; push — відправлення commit на GitHub. Гілка `practical-05` містить нову роботу окремо від `main` ПР №4.

## 2. Відкрити готову папку у VS Code

1. Запустіть VS Code.
2. Виберіть File → Open Folder… / Файл → Відкрити папку.
3. Відкрийте папку `outputs/practical-05-lume` всередині цієї робочої папки Codex. Повний шлях надано в повідомленні з результатом.
4. Якщо VS Code запитує довіру до вашого проєкту, виберіть Yes, I trust the authors.
5. Ліворуч мають бути `index.html`, `login.html`, `register.html`, `product-form.html`, папки `styles`, `images`, `docs`, `evidence`.
6. Знизу зліва перевірте назву гілки: `practical-05`.
7. Не натискайте Initialize Repository: Git у цій папці вже є.

Якщо хочете працювати саме у своїй старій локальній папці ПР №4, дивіться альтернативу в кінці інструкції. Не перемішуйте ці два способи.

## 3. Подивитися й зрозуміти CSS

1. Розкрийте `styles`, відкрийте `main.css`.
2. Натисніть Ctrl+F, знайдіть `.container`. `inline-size: min(100% - 2rem, 80rem)` залишає поля та обмежує максимальну ширину.
3. Знайдіть `.collection-list`. Grid із `auto-fit` автоматично обирає кількість карток у рядку.
4. Знайдіть `.form-actions`. Flexbox переносить кнопки, коли вони не поміщаються.
5. Знайдіть `@media (min-width: 44rem)`: дві колонки hero й горизонтальний пошук з'являються, коли для них достатньо місця.
6. Знайдіть `@media (min-width: 72rem)`: повний header поміщається в рядок.
7. Знайдіть `prefers-reduced-motion`: переходи вимикаються за відповідним налаштуванням.

Пояснення: `gap` — проміжок між елементами; `1fr` — частка вільного простору Grid; `minmax()` — межі ширини колонки; `flex-wrap: wrap` — дозвіл переносу; `overflow-wrap: anywhere` — перенос дуже довгого рядка. HTML-порядок при цьому не переставляється.

## 4. Запустити сайт без термінала

Найпростіший спосіб: відкрийте папку у Провіднику й двічі натисніть `index.html`. Вона відкриється у браузері. Після змін зберігайте файл у VS Code через Ctrl+S та оновлюйте браузер Ctrl+R.

Для автоматичного оновлення можна скористатися Live Server, якщо він у вас уже встановлений: правою кнопкою по `index.html` → Open with Live Server. Для цієї практичної розширення не обов'язкове.

Перевірте посилання на вхід, реєстрацію та форму товару. Пошук не фільтрує товари; форми ще без сервера. Помилка після коректного POST не означає помилку CSS.

## 5. Перевірити розміри екрана

1. Відкрийте головну в Chrome або Edge.
2. Натисніть F12 або Ctrl+Shift+I.
3. Натисніть Ctrl+Shift+M, щоб увімкнути панель розмірів.
4. У списку пристроїв оберіть Responsive, щоб вводити ширину вручну.
5. Послідовно введіть 320, 360, 390, 430, 768, 900, 1280, 1440. Висоту можна встановити 900.
6. На кожній ширині прокрутіть сторінку зверху вниз. Перевірте меню, пошук, картки, зображення й кнопки.
7. Повторіть на `login.html`, `register.html`, `product-form.html`.
8. Додатково перевірте 703/704 і 1151/1152, щоб побачити переходи композиції.

Очікування: на телефоні hero й каталог вертикальні; на 768px hero має дві колонки, каталог — дві; на 1280px каталог має чотири картки в рядку. Усі посилання доступні; горизонтальної прокрутки всієї сторінки немає.

Якщо DevTools відкритий збоку й для 1280px не вистачає місця, у меню DevTools змініть Dock side на окреме вікно.

## 6. Справжній масштаб браузера 200%

1. Вимкніть режим пристрою через Ctrl+Shift+M і закрийте DevTools.
2. Розгорніть браузер.
3. Відкрийте меню браузера з трьома крапками й у Zoom / Масштаб виставте 200%.
4. Перевірте всі чотири сторінки: текст, доступність меню, кнопок і полів; відсутність перекриття й горизонтальної прокрутки.
5. Збережіть скриншот та запишіть фактичний результат у README і `docs/REPORT.md`.
6. Поверніть 100% через Ctrl+0.

Масштаб картинки в панелі пристроїв та CSS `zoom: 2` не замінюють цей крок. Автоматичний аудит перевірив CSS zoom, але не виконав браузерний zoom замість вас.

## 7. Клавіатура, форми, reduced motion

**Клавіатура:**

1. Оновіть сторінку, натисніть Tab. Має з'явитися «Перейти до основного вмісту».
2. Натисніть Enter: перехід до main.
3. Далі рухайтеся Tab і назад Shift+Tab. Видима рамка має супроводжувати активний елемент, порядок — відповідати читанню.
4. Enter активує посилання/кнопку; Space перемикає checkbox. Для групи radio перевірте клавіші зі стрілками.
5. На формах натисніть кнопку надсилання з порожніми обов'язковими полями: браузер повинен заблокувати надсилання.

**Reduced motion:**

1. Відкрийте DevTools.
2. Натисніть Ctrl+Shift+P усередині DevTools; введіть `Show Rendering` і виберіть відповідну команду.
3. У Rendering знайдіть Emulate CSS media feature prefers-reduced-motion, виберіть `reduce`.
4. Наведіть на кнопки/посилання: зміна кольору має відбуватися без переходу.
5. Поверніть No emulation.

**Довгий текст і кількість карток:**

У DevTools → Elements тимчасово змініть назву картки на довгий рядок без пробілів. Перевірте, що він переноситься. Для порожнього/великого каталогу можна тимчасово видалити/дублювати `li` всередині `.collection-list`. Зміни у DevTools не зберігаються у файли; Ctrl+R повертає початковий вміст. Автоматичний аудит уже перевіряв 0 та 24 картки.

## 8. Перевірити overflow

Швидка перевірка: сторінка не повинна їздити вліво-вправо. Точніша — DevTools → Console; вставте й натисніть Enter:

```javascript
document.documentElement.scrollWidth > document.documentElement.clientWidth
```

`false` означає, що ширина сторінки не перевищує доступну. Якщо `true`, знайдіть кандидатів:

```javascript
[...document.querySelectorAll('body *')].filter(el => {
  const r = el.getBoundingClientRect();
  return r.right > document.documentElement.clientWidth + 1 || r.left < -1;
})
```

Серед результатів може бути прихований поза екраном skip-link до фокусу — це очікувана поведінка. Для решти перевіряйте фіксовані ширини, min-width, padding та нерозривний текст. Не приховуйте проблему через `overflow-x: hidden` на body.

## 9. Заповнити README і матеріал для звіту

1. У VS Code відкрийте `docs/REPORT.md`.
2. Впишіть ПІБ, групу, дату та свої результати ручних перевірок.
3. Відкрийте README і змініть запис про browser zoom лише після власної перевірки, наприклад: «Browser zoom 200%: перевірено вручну [дата], усі 4 сторінки, перекриттів не виявлено» — якщо це ваш фактичний результат.
4. Збережіть Ctrl+S.
5. Markdown можна переглянути красиво: Ctrl+Shift+V.

У `evidence` уже є результати автоматичного аудиту й 12 знімків. Додайте власні скриншоти zoom 200%, focus та GitHub до звіту. Якщо викладач вимагає DOCX/PDF, перенесіть матеріал зі звіту у його шаблон і вставте зображення. Файл Markdown сам по собі не є оформленим DOCX-звітом.

## 10. Commit у VS Code

1. Натисніть Ctrl+Shift+G — відкриється Source Control.
2. Перевірте, що працюєте саме з папкою LUME і гілкою `practical-05`.
3. Натисніть змінений файл, щоб переглянути різницю. Зелене — додано, червоне — вилучено.
4. Натисніть `+` біля потрібних файлів, щоб додати їх до Staged Changes. Для всіх перевірених файлів — `+` біля Changes.
5. У полі повідомлення введіть, наприклад `docs: record manual responsive checks`.
6. Натисніть Commit.

Якщо у підготовленій папці основні зміни вже закомічені, ви зберігаєте тут тільки свої доповнення до звіту. Якщо Changes порожній, новий commit не потрібен.

Якщо Git уперше просить ім'я та email, це одноразове налаштування. Відкрийте Terminal → New Terminal і виконайте дві команди зі своїми значеннями:

```powershell
git config user.name "Ваше ім'я"
git config user.email "Ваш email GitHub або noreply-адреса з налаштувань GitHub"
```

Команди без `--global` налаштовують тільки цей репозиторій. Після цього повторіть Commit.

## 11. Відправити в GitHub

1. У Source Control натисніть Publish Branch, якщо гілка ще не опублікована. Для вже опублікованої — Push або Sync Changes.
2. За потреби увійдіть у GitHub у браузері й підтвердьте доступ VS Code до свого облікового запису. Пароль або token у чат надсилати не потрібно.
3. Відкрийте `https://github.com/aemuw/practical-04-lume`.
4. У списку гілок замість `main` виберіть `practical-05`.
5. Переконайтеся, що README починається з «Практична робота №5» та є новий commit.
6. Скопіюйте URL гілки: `https://github.com/aemuw/practical-04-lume/tree/practical-05`.

Це посилання коректне для здачі після успішного push. Основна гілка ПР №4 залишається окремою версією. Merge у main для цієї схеми не потрібний.

Якщо викладач вимагає окремий репозиторій `practical-05-lume`, створіть на GitHub порожній public repository з такою назвою без README/license/.gitignore. У Terminal VS Code додайте ще один remote, зберігаючи зв'язок із ПР №4:

```powershell
git remote add practical05 https://github.com/aemuw/practical-05-lume.git
git push practical05 practical-05:main
```

Тоді посилання для здачі — `https://github.com/aemuw/practical-05-lume`. Цей варіант виконуйте тільки якщо справді потрібен окремий репозиторій; стандартний шлях вище вже використовує Git і GitHub.

## Альтернатива: зміни у вашій старій локальній папці

1. У VS Code відкрийте свою папку `practical-04-lume`.
2. Перевірте Source Control. Якщо є незбережені зміни попередньої роботи, спочатку збережіть їх у commit.
3. Ctrl+Shift+P → `Git: Create Branch…` → введіть `practical-05`. Якщо така гілка вже існує, перемкніться на неї замість повторного створення.
4. У готовому `styles/main.css` із цієї роботи натисніть Ctrl+A, Ctrl+C.
5. У `styles/main.css` вашої старої папки натисніть Ctrl+A, Ctrl+V, Ctrl+S.
6. Так само перенесіть README; скопіюйте папки `docs`, `evidence`, `tools` і доповніть `.gitignore` рядком `node_modules/`.
7. Не копіюйте папку `.git` поверх своєї. Вона містить вашу історію та налаштування.
8. Виконайте перевірки, Commit із повідомленням `feat: complete practical 05 responsive layout`, потім Publish Branch.

Офіційні довідки: [Git у VS Code](https://code.visualstudio.com/docs/sourcecontrol/quickstart), [гілки](https://code.visualstudio.com/docs/sourcecontrol/branches-worktrees), [репозиторії та remotes](https://code.visualstudio.com/docs/sourcecontrol/repos-remotes).
